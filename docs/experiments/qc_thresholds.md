# 촬영 종류별 영상 품질 기준값 산정 근거 (`QC_THRESHOLDS_VERSION = "v1"`)

## 1. 측정 지표 정의 (입력: 8-bit 0~255 윈도우잉 완료 2D 단면)
- **밝기 (`brightness`)**: 전체 픽셀 평균 휘도 ($\mu$)
- **대비 (`contrast`)**: 전체 픽셀 표준편차 ($\sigma$, RMS Contrast)
- **선명도 (`sharpness`)**: 2D Laplacian 필터 응답의 분산 ($\text{Var}(\nabla^2 I)$)

- **측정 대상**: 프로젝트 변환·학습 완료 전체 **626장**(`train 404 / val 100 / test 122`) 및 평가 분할 **`test` 122장**
- **윈도우잉 비교 조건**:
  1. **자동 윈도우 (`apply_window(pixels)`)**: 1%~99% 백분위 선형 스트레칭 (`prepare_spinexr.py` 공통 전처리 기준)

## 5. 현행 `QC_THRESHOLDS["DX"]` 적정성 평가 및 확정 근거

1. **`brightness_min = 35.0`, `brightness_max = 220.0` (적정 — v1 확정 유지)**:
   - 자동 윈도우 기준 실측 범위는 `30.46 ~ 202.02`(p5~p95: `70.89 ~ 155.69`)이며, 하한 `35.0`은 실제 광범위 암부 저휘도 이상치(`12dd72dad9...`, `30.46`)를 정확히 걸러낸다(헤더 WL 기준 하위 0.3%인 2건 검출).
   - 상한 `220.0`은 임상 보관 데이터 최고 휘도(`202.02`)보다 충분한 여유를 두어 정상 고휘도 영상(`d062d5b9...`, `178.73`)의 오탐을 막고, 실제 과노출·백화(whiteout) 촬영 오류만 선별하도록 설계되었다.
2. **`contrast_min = 25.0` (적정 — v1 확정 유지)**:
   - 자동 윈도우 적용 시 동적 범위가 0~255로 정규화되므로 최소값이 `32.74`로 오탐 0건이며, 원장비 헤더 WL 기준에서는 최소 `17.73`까지 떨어지는 저대비 영상 **8건(1.3%)**을 유효하게 검출한다.
3. **`sharpness_min = 50.0` (자동 윈도우 기준 v1 확정 유지, 향후 v2 검토 제안)**:
   - 자동 윈도우 기준 `p10 = 42.36`, `p25 = 73.60`으로, 현행 `50.0`은 전체의 **86.1%를 통과**시키고 하위 약 13.7%(86건, 대표 흐림 샘플 `15.32` 포함)를 재촬영 점검 대상으로 선별하는 합리적 기준이다.
   - **향후 v2 조정 제안 (코드 변경 없이 문서 제안으로 기록)**: 실제 서비스에서 자동 윈도우가 아닌 **DICOM 헤더 WL 원본 그대로** QC를 실행할 경우 `sharpness < 50.0` 비중이 **24.3%(152/626장)**까지 높아져 재촬영 경고가 다소 보수적으로 작동할 수 있다. 헤더 WL 기준 운영 시 알람 피로도가 문제 된다면 `sharpness_min`을 `30.0~35.0` (`p5~p10` 구간: `21.42~29.05` 직상단)으로 완화하는 v2 개정을 팀 합의 후 검토할 수 있다.
4. **결론**: 현행 `QC_THRESHOLDS_VERSION = "v1"` (`DX`: `35.0 / 220.0 / 25.0 / 50.0`)은 자동 윈도우 전처리 파이프라인 기준 실측 분포(통과율 86.1%)와 대표 5종 판정 결과에 모두 부합하므로 **코드 수정 없이 v1 기준값으로 확정**한다.
